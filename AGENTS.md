# AGENTS.md

Instructions for any coding agent working in this repository. `CLAUDE.md` only points here; keep
repository guidance in this one file.

## What this repo is

A library of general-purpose agent skills. Each skill is a folder `skills/<name>/` with a `SKILL.md`
and optional `references/` and `scripts/`. There is no application to build; the skills are the
product. `scripts/cli.mjs` (bin `ai-agent-skills`, Node 22+, no dependencies) installs, updates and
validates them on Windows, macOS and Linux. Install, update and uninstall are documented in
[docs/install.md](docs/install.md); coexistence with the Factory repository in
[docs/coexistence.md](docs/coexistence.md).

## Commands

```bash
node scripts/cli.mjs validate                 # the CI gate; run before every commit
node scripts/cli.mjs list
node scripts/cli.mjs install [names...] [--copy|--link] [--target <t,..>|--dest <path>]
node scripts/cli.mjs update [names...] [--check] [--no-pull] [--force] [--adopt] [--prune]
node scripts/cli.mjs autoupdate [--install|--remove] [--job-only|--hook-only]
node --test scripts/cli.test.mjs              # CLI tests (temp HOME per test; never the real one)
```

The skill tests CI runs are listed in `.github/workflows/validate.yml`; a new test file must be
added there.

## What the validator enforces

1. The folder name equals the frontmatter `name:`, and the frontmatter has `name:` and
   `description:`. A mismatch installs the skill under the wrong name.
2. Every `.sh` a `SKILL.md` invokes is bundled in the repository or generated by the skill itself.
   Otherwise the call fails with exit 127.
3. Every relative Markdown link in a `SKILL.md` or its `references/` resolves.
4. Every file under `references/` is reachable from `SKILL.md` by a link or a named path.
5. Retired vocabulary stays retired. The list is `RETIRED_VOCABULARY` in `scripts/cli.mjs`; add to it
   when you delete a concept so no file can keep naming it. It also applies to this file.
6. A skill that defines an `OUTCOME_VOCABULARY` lists `PASS`, `FAIL`, `NOT_TRIGGERED`,
   `NOT_APPLICABLE` and `DEGRADED`, and at most one file in the library defines it.

## Conventions

- **Independence.** No skill links into another repository. A skill from the Factory repository
  (`code-quality`, `test-quality`, `docs-accuracy`, `vapt`, `generate-ticket`, `ship-ticket`) is named
  as an optional companion in plain text, never as a relative link, and the citing skill documents
  what it does when the companion is absent.
- **Vendored skills.** `skills/security-audit` comes from cloudflare/security-audit-skill through
  `external-skills.json` and `scripts/sync-external.mjs`, refreshed daily by
  `.github/workflows/sync-external.yml`. Never edit it by hand: the next sync overwrites it.
- **Identifiers.** The manifest, state directory, scheduled-job labels and SessionStart hook are
  this library's own (docs/coexistence.md). Do not reuse the Factory repository's names.
- **Isolation in tests.** Tests run the CLI against a temporary HOME and never call
  `autoupdate --install` or `--remove`, which would register a real scheduled job.

## Privacy expectations

This repository is public. In anything you commit (code, docs, tests, commit messages):

- use neutral project names, ticket IDs and examples (`acme-shop`, `TICKET-123`), never a real
  private project, customer or tracker key;
- add no session URLs or session trailers to commits; a `Co-Authored-By` line is fine;
- include no personal filesystem paths (use `~` or placeholders), e-mail addresses other than
  GitHub noreply ones, or credentials and tokens.

This is a convention for contributors and agents. No CI check enforces it.
